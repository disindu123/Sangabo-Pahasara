# Verification · SCMU official website

Validated on 16 October 2026 using Node 24.19.0. Node 22+ is supported.

- `npm run build`: Firebase Auth browser bundle (Storage SDK removed) built; all five page entrypoints and their imports resolved.
- `npm test`: 32 passing API/service/runtime tests. Coverage includes the role matrix, feedback/privacy, revocation and disabled accounts, URL validation, maintenance, IP blocks, ten-attempt login protection, concurrency, account recovery, last-admin protection, owned uploads and idempotent registration.
- `npm run test:rules` (last run 11 October; rules unchanged): 7 passing integration scenarios using the demo Firestore and Storage emulators. Direct Firestore access is denied; all retired Firebase Storage uploads are denied for every role, including requests carrying old upload permits. Actual Firestore transactions and pagination are exercised.
- `npm run test:browser`: 23 passing scenarios with Chromium 153. Desktop (1440 px) and mobile (390 px), slideshow controls, event dialog/notifications, live/board visibility, feedback, grouped albums, lazy images/lightbox, role dashboards, sign-in/logout, file-input publishing, account creation/role editing/delete/cancel, all-role event photo publishing and homepage updates and no hardcoded fallback, moving underline, reduced motion, drag/drop previews and clearing in all four image controls, invalid/multiple-file rejection and locked selection during upload, Cloudinary multipart failure/retry, Sinhala heading at 320–1440 px, IP unblock and maintenance/live switches. The favicon loading state renders correctly and disables its pulse with reduced motion. Real canvas-generated PNG/JPEG uploads verify smaller transmitted files, matching permit MIME/bytes, 2400 px sizing, transparency, phone EXIF orientation, prepared-file reuse on retry, preservation of small/animated formats, decoder/encoder fallbacks and concurrent list/count refreshes.
- `npm run format:check`: source formatting checked.
- `npm audit --omit=dev` (11 October): zero known production dependency vulnerabilities at that check. No dependencies changed in the redesign.
- `git diff --check`: no whitespace errors. The deployment entrypoints load in ESM without CommonJS `require(esm)` support.

The 16 October redesign also received visual checks on Home, Gallery, Contact, Login and 404 at 320, 390, 768, 1024 and 1440 px. No horizontal document overflow was detected. Maintenance and restricted-access screens were checked at 320, 390 and 1440 px. Browser layout measurements verified the notification dismissal button remains at the right content edge. Desktop/mobile screenshots were reviewed for the masthead, Sinhala title, photo archive, contact form, committee and login. These checks use local fixtures; published media and accounts are not modified.

API/service tests inject doubles. Browser tests replace the Firebase SDK with a **test-only** adapter and run the actual Express routes against an in-memory store; external video/image responses are intercepted. Browser upload tests intercept Cloudinary HTTP responses and verify multipart upload, UI progress, error/retry behavior and permit registration. Image preparation uses the real browser canvas and image decoder; multipart payload sizes and formats are checked against the actual permit requests. This verifies byte savings, not upload timing on a live network. Cloudinary metadata/signature/ownership/deletion checks use service doubles; retired Storage rules are tested against the real local emulator. No bypass, sample login, or test account is enabled in production.

No live Cloudinary or Firebase project, credentials or hosting deployment was tested. Before launch, follow the README to verify actual IAM, Auth, Firestore/Storage rules, uploaded photographs and the host’s true client-IP forwarding on staging. Firebase rules deployment is essential; a local passing test does not install rules in the real project.

The previous `.env.example` contained Admin/provider secret values. This revision replaces them with placeholders; revoke/rotate previously exposed credentials, including those in git history.
